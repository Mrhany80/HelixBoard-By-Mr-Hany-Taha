# v2.7.0 audit

## Baseline
- 2.6.1: 25/25 suites. Preview build merged into `release/2.7.0`: 24/25 — `mm` failed only because the test answered the
  old browser prompt; the app now asks for linking words in its own box. Test updated → 25/25.

## B1 — slideshow click and key flow
- Keys: `deck.js` keydown → if a text box is open: Esc commits; PageDown/PageUp commit and continue; other keys type.
  Otherwise Space/Enter/PageDown/→ = next, ←/PageUp/Backspace = back, regardless of the tool.
- Click: the laser advances; the pen draws (a hint shows ▶ and the keys).
- Repro and result (tests/ppt.js, 400 strokes + 20 text boxes on the slide, pen on, mixed inputs, selection, open text box):
  | | moved | key → step |
  |---|---|---|
  | 2.6.1 | 18 / 20 (PageDown with a text box open did nothing) | 1.3–3.8 ms |
  | 2.7.0 | 20 / 20 | 0.6–2.1 ms |
- Frames during a fade, 400 strokes: ~17 ms (software rendering in CI), same as with no strokes.

## B2 — right-click paths
- `input.js`: one capture `contextmenu` handler on `document` (text fields excepted); `pointerdown` button 2 and the
  touch long-press both go through `radial()`, which records `menuAt`; any second trigger within 700 ms is ignored.
- Dock buttons and tabs keep their own `oncontextmenu` actions (remove from dock, tab menu) and preventDefault.

## B3 — duplicate tools
- Runtime inventory over `HBUI.ALL` and every tab: no label on two ids. Tools taken out of tabs (still in `ALL`, so saved
  docks keep them): `n_tps`, `calcp`, `t_tps`, `t_seq`, `ss_quiz`, `ss_cards`, `record`, `anim2`. Earlier duplicates
  listed in the brief (Think time, Stopwatch, QuickShape, Projector, Mini picker, Command words, Apparatus) were already
  single in 2.6.1.

## B6 — data flow
Teacher app (settings, document pages, key) → `HBQB.store` (IndexedDB) → `cl:cmd testStart` (def with key, kept on the
teacher's computer) → class link server → phones get `studentCopy` (no `a`), pages via `/t/doc`, answers `/t/ans`,
`/t/submit`, flags `/t/flag` → marked by `desktop/testgrade.js` → `testResults` → dashboard (`testdash.js`).

## Risks
- The exam depends on the teacher's computer staying on (stated in the settings).
- Word → PDF needs the Windows app; the web version asks for a PDF.
- Paper scanning is not in this release.
