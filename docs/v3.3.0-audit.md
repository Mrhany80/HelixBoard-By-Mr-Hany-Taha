## Findings after checking
- **H1 XSS (revised, downgraded to Medium, still open).** 157 `innerHTML =` assignments. The ones I read in `wheel.js` and `timer.js` pass user text through `HB.esc()`, so the "140 unescaped sinks" worry from the static count is not confirmed. Not yet checked: `ui.js` (31), `studio.js` (16), `plus.js` (13), `sci_bio.js` (10), imported DOCX/PPTX text, `.hbset` fields. No CSP exists. A strict CSP is hard because the build is one file with inline scripts; a realistic CSP needs nonces or hashes generated by `build.py`. To do: automated payload test over each sink.
- **H2 silent failures (confirmed).** 40 empty or return-only catch blocks in `app/`, e.g. `HB.set.put` swallows localStorage write errors. Save paths still to be traced one by one.
- **H4 CI and test portability (fixed in part).** Tests hard-coded `/home/user/helixboard` in 12 files; now resolved from the test file location. Still open: no CI job runs tests before the release workflow publishes. The `sweep` and `ppt` suites are too slow to run in one short command.
- **Release risk (confirmed).** `.github/workflows/release.yml` builds and publishes on any push to `main` whose version has no release.
- **Stroke commit and first-ink are over their own targets** at 4x CPU slowdown. Needs a profile before any ink change.
- Not yet verified: H3 data safety, H5 updater, M1 Supabase policies, M2 service worker, phone/iPad layouts, a11y.
